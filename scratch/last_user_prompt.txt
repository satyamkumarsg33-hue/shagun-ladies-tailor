BUG 2 — LUXE WORKFLOW IS SKIPPING MEASUREMENT LOGIC
==================================================

The reported problem:

A customer enters the Luxe Stitching process and eventually reaches the next page/review/order stage, but the measurement requirement has effectively been skipped.

IMPORTANT ARCHITECTURE DECISION:

Measurement must NOT be determined globally by "Standard Stitching" vs "Luxe Stitching".

Measurement/reference information belongs to EACH PHYSICAL GARMENT.

For every garment in the order, the system must know how its fitting/measurement requirement will be handled.

Current allowed customer-facing choices are:

1. Reference Blouse
2. Visit Shop

The customer must NOT enter numerical measurements online.

Required logic:

A. REFERENCE BLOUSE

If a garment has selected "Reference Blouse":

- Treat its measurement requirement as satisfied.
- Preserve the selected reference-blouse information through the complete order workflow.
- Do not ask the customer for numerical measurements.
- Do not ask for the same measurement choice again later.

B. VISIT SHOP

If a garment has selected "Visit Shop":

- Treat the measurement method as valid.
- Mark the garment as measurement pending / visit-shop required according to the existing architecture.
- Do not force the customer to enter numerical measurements.
- Preserve this state through cart, order creation, admin, and dossier.

C. MISSING MEASUREMENT METHOD

If a garment has neither:
- Reference Blouse
nor
- Visit Shop

then the workflow MUST NOT silently continue.

Instead:
- stop the workflow at the appropriate step,
- clearly ask the customer to select how measurement will be handled,
- allow them to continue only after one valid method is selected.

D. EXISTING STANDARD STITCHING DATA

If the same physical garment already has valid measurement/reference information collected during the Standard Stitching flow:

- Reuse it.
- Do NOT ask for it again.
- Do NOT overwrite it with null/default data.

If it does not have valid measurement information:

- Require the measurement method before the garment can be finalized.

E. MULTIPLE PEOPLE / MULTIPLE GARMENTS

This must work independently for every garment.

Example:

Person: Riya

Garment 1: Blouse
Measurement: Reference Blouse
Status: satisfied

Garment 2: Saree
Measurement: Visit Shop
Status: measurement pending

Garment 3: Lehenga
Measurement: missing
Status: cannot finalize until user chooses Reference Blouse or Visit Shop

Do not create one global "measurement complete" flag for the entire order.

F. WORKFLOW NAVIGATOR

The existing smart workflow navigator must understand the measurement state of every garment.

It must not simply say:

"Standard = measurement skipped"

or

"Luxe = measurement required"

Instead it should evaluate each garment's actual measurement/reference state.

The customer should be prevented from reaching final review/order submission while any garment has a missing measurement method.

IMPORTANT:
Do not introduce numerical measurement entry fields.
